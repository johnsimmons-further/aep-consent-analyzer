How Adobe Experience Platform Processes Visitor Consent

            

              Synthesized directly from the official Adobe Experience League Consent Processing documentation
            

          

        


        

          

            

              1. Client-Side Collection (`defaultConsent` & `setConsent`)
              Read SDK Docs ↗
            

            

              The AEP Web SDK (`alloy`) does not connect to CMPs out of the box. You configure `defaultConsent` (`"pending"`, `"in"`, or `"out"`) during `alloy("configure", ...)`. When set to `"pending"`, all `sendEvent` calls are held in an in-memory queue and no ECID cookie (`kndctr_<orgId>_AdobeOrg_identity`) is created until `alloy("setConsent", ...)` is invoked. Once invoked, the visitor's choice is cached for 180 days in `kndctr_<orgId>_AdobeOrg_consent` (`general=in` or `general=out`).
            

          


          

            

              2. Profile-Enabled Dataset & Schema Field Group
              Read Dataset Docs ↗
            

            

              Consent data must be routed via your Datastream to a Profile-enabled dataset based on the XDM Individual Profile class using the Consents and Preferences field group (`consents`). Note: Consent data sent inside an XDM ExperienceEvent dataset (`interact` hits) is not honored by downstream AEP consent enforcement workflows!
            

          


          

            

              3. XDM `Consents and Preferences` Data Type vs. Field Group
              Read XDM Docs ↗
            

            

              The standard Profile field group provides `consents.collect.val` (automatically enforced by Web SDK), `consents.share.val`, `consents.personalize.content.val`, `consents.marketing.*` (`preferred`, `any`, `email`, `push`, `sms`, `call`, `directMail`), and `consents.metadata.time`. Specifically on Profile schemas, the field group removes `adID` and adds `idSpecific` (`consents.idSpecific.<namespace>.<id>`) for identity-granular preferences.
            

          


          

            

              4. Real-Time Customer Profile & Merge Policies
              Read Overview Docs ↗
            

            

              Always include `consents.metadata.time` (ISO 8601 timestamp) when calling `setConsent`. Real-Time Customer Profile uses Timestamp-Ordered Merge Policies (or Dataset Precedence) to ensure a customer's newest consent update overrides older profile fragments.
            

          


          

            

              5. IAB TCF 2.0 Support (Adobe Vendor ID 565)
              Read IAB TCF 2.0 Docs ↗
            

            

              When using an IAB TCF 2.0 CMP, pass `standard: "IAB TCF"`, `version: "2.0"`, and `value: tcData.tcString` to `alloy("setConsent", ...)`. Adobe Experience Platform's registered TCF 2.0 Vendor ID is 565, and your CMP must have a valid registered IAB CMP ID for AEP to enforce TCF 2.0 consent downstream.
